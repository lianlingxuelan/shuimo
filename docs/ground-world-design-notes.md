## 1. 渲染管线（先做对，否则立刻紫屏）

- `ProjectSettings/GraphicsSettings.asset` 中 `m_CustomRenderPipeline = {fileID: 0}` → 项目当前是 **Built-in（内置）渲染管线**。
- HDRP / URP 只是昨天导资产包时被连带装进 `manifest`，列在 `m_SRPDefaultSettings` 里但 **未激活**。
- 我们的水墨地面 `InkGround.shader` 是 Built-in 兼容，且已改 **Unlit**（宣纸白，解决无光发黑）。

**新手红线**
- ❌ 不要在 Package Manager 里激活 HDRP / URP（全项目材质集体紫屏，要重做）。
- ✅ 地面材质选 **Xianxia/Ink/InkGround** 或 Built-in **Standard**；勿选 HDRP/URP 开头的 Lit。
- ✅ Unity 的 3D 模板默认就是 Built-in + Standard，和本项目同一条管线，不会不兼容。

## 2. 地面做法：是连续平面，不是「洒」

- 竹林是 N 根独立物体，所以才用程序化「撒点」；**地面是连续 mesh，不需要撒点**。
- 推荐：**单一大 Plane 覆盖整个活动区**，只占 1 个 draw call，Batches 不涨。
- 将来若做「区块流式加载（走到哪加载哪块地表）」，才需要切成小块拼铺；原型阶段整块最简单。

---

## 3. 当前活动区域尺寸（代码硬数据）

| 项 | 值 | 来源 |
|----|----|------|
| 单格尺寸 TileUnit | 32 世界单位 | `WorldBuilder.TileUnit` |
| 默认地图格数 | 120 × 80 | `WorldBuilder.BuildScene` 默认 |
| **活动区 WorldWidth × WorldHeight** | **3840 × 2560** 世界单位 | `Width*TileUnit` / `Height*TileUnit` |
| 竹林撒点范围 groveHalfExtent | ±700（中心 1400×1400 子区） | `BambooSceneContext.groveHalfExtent` |
| 玩家闪避位移 | ~130 单位 | `DODGE_DISTANCE` |

- 3840×2560 这个矩形就是 **相机钳制**（`CameraFollow.clampToWorld`）与 **玩家移动钳制**（`PlayerController`）的边界——即实际能走到、镜头能拍到的「全图」。
- 竹林目前只在中心 1400×1400 子区内，是活动区的一部分（非全图铺满）。

## 4. 地面施工注意点（按踩坑优先级）

🔴 **必看（不做立刻翻车）**
- 地面尺寸至少 ≥ 活动区（建议直接覆盖 3840×2560），否则走到边缘看到「地面外虚空/黑」。
- 高度对齐 `y = 0`：地面、竹林根部、玩家脚底都按 0 起，三者对齐才不悬空。
- 给碰撞：Plane 自带 Mesh Collider，让角色站得住、不穿地。

🟡 **风格 / 性能**
- 材质用 `Xianxia/Ink/InkGround`（宣纸白、Unlit 不受光，和竹林同调且不用打光）或 Built-in Standard。
- 一个 Plane = 1 draw call，零压力；用 Terrain（地形）会多几个 batch，但量级可控；别堆一堆独立小网格当地面。

🟢 **后续扩展**
- 将来做「不同区域不同地表」（草地/石板/水边）再切分或叠 decal，现在先单块。

## 5. 2.5D 与真 3D 概念澄清

用户原理解：「2.5D = 3D 场景固定相机，3D = 自由视角」——**只对一半**。

- **2.5D（本项目）** = 3D 引擎 + **固定/受限相机** + **2D 表现**（纸片人精灵、按深度排序）。相机角度锁死（俯视/等距），玩家不能转视角。
- **真 3D** = **自由相机**（可 360° 绕角色）+ **全 3D 角色模型**（可跳可爬可环视）。
- 本质差异在 **相机控制 + 角色表现 + 玩法维度**；「固定 vs 自由相机」只是相机控制策略，不是分界线。
- **二者共用同一套引擎、同一 Built-in 管线、同一个 Plane/Mesh**——所以你用 3D 模板做地面，对 2.5D 完全适用，将来切真 3D 也不冲突。

## 6. 地面要不要做高低起伏（地形高程）？

**结论：可行且 2.5D 里常见，但本里程碑阶段建议保持平铺，高程留作后续增强。**

- 2.5D 做高低台很正常（Diablo 式等距也有上下层）。
- 但本项目当前是「平面 + 纸片人精灵 + 深度排序」：一旦地面有高程，角色要「踩在斜坡上」必须额外做：
  1. 地面用高度图（Unity Terrain 或位移平面）；
  2. 玩家/敌人每帧**采样地面高度设自身 y**（否则脚悬空或穿地）；
  3. 深度排序与脚底对齐重新调校，且相机需足够陡的等距角才不穿帮。
- 水墨风本就偏平面，平铺更贴风格；高程工程量不小，现在做属于过度设计。
- **后续路线**：高度图地形 + 角色 y 跟随采样（表现层在 `PlayerController` 落地高度处接入）。

## 7. 用户本地落地步骤（最快路径）

1. Hierarchy 右键 → 3D Object → **Plane**。
2. Inspector → Rotation **X = -90°**（平面默认竖着，转平躺）。
3. 新建 Material → Shader 选 **Xianxia/Ink/InkGround** → 拖到 Plane。
4. 缩放使 Plane 覆盖 ~3840×2560（或你确认的游玩范围）。
5. 确认 Mesh Collider 在（让角色站得住）。
6. `Shuimo/Scene/Force Recompile` → PlayMode 看效果：地面宣纸白、角色不穿地、竹林落在地面上。
