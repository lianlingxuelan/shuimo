# 竹林 2.5D 技术验证计划

> 分支：`feature/2.5d`（从 `main` 切出，`main` 保留 2D 可玩版不动）
> 启动日期：2026-08-10
> 主理：齐活林（SoftwareCompany 工作流）
> 目标：用**最小成本**验证「3D 场景 + Spine 骨骼角色 + 重特效打击感」在 Unity 里是否可行、手感对不对。验证通过再正式切，不通过则留在 2D，主线零损失。

---

## 0. 为什么是"验证"不是"切换"

基于已确认的两点（见对话可视化结论）：

1. **架构隔离**：战斗内核是纯 C#、零 UnityEngine 依赖的独立层；2D 与 2.5D 只是最底下的"表现层"。切换方向时内核一行不用改。
2. **分支零成本回退**：`main` 永远保留 2D 可玩版；`feature/2.5d` 专门做技术验证。不顺眼就 `git checkout main`，瞬间回 2.0。

所以本计划**不切换主线**，只在分支上探路。

---

## 1. 验证目标（三个子项）

### 1.1 竹林 3D 场景表现力
- **目标**：真 3D 几何体（竹竿 Cylinder + 竹叶面片 + 水墨地面 + 薄雾粒子）组成可行走竹林；摄像机斜上 45° 俯视，竹子间有正确遮挡与景深。
- **做法**：搭一个 `BambooGrove` 场景，放 20–30 根 3D 竹子 + 地面 + 雾层。
- **真机验收（用户看）**：
  - [ ] 进场景看到的是 3D 竹林，不是贴图背景
  - [ ] 角色在竹子间有正确遮挡 / 景深
  - [ ] 水墨感（竹边墨晕、留白）达标
- **风险**：水墨 Shader 调参耗时 → 先用 URP Lit 占位材质，后换水墨。

### 1.2 Spine 角色手感
- **目标**：女主改为 Spine 骨骼动画（Billboard 面向相机），八方向移动时动画过渡自然。
- **做法**：导入 Spine Unity 运行时，把现有 39 帧精灵替换为 Spine 骨骼（或先用占位骨骼验证管线）。
- **真机验收**：
  - [ ] Spine 角色能播 idle / walk / attack
  - [ ] 八方向移动时动画混合不突兀
  - [ ] 面向相机（Billboard）正确
- **风险**：Spine 运行时导入；骨骼美术需重做（成本已评估低于逐帧，见 `unity-2.5d-feasibility.md`）。

### 1.3 砍竹子特效与反馈
- **目标**：玩家攻击竹子 → 竹子断裂/晃动 + 墨迹/竹叶粒子飞溅 + 顿帧 + 伤害飘字，验证"打击感"在 3D 空间里成立。
- **做法**：复用现有战斗内核（攻击判定 / 伤害），在 3D 空间触发粒子特效 + 现有 `FeedbackClock` 顿帧。
- **真机验收**：
  - [ ] 攻击命中竹子有断裂 / 晃动反馈
  - [ ] 粒子特效（墨迹 / 竹叶）层次感强于 2D
  - [ ] 顿帧 / 屏震 / 飘字仍生效（内核复用）
- **风险**：3D 粒子与 2D 顿帧协调 → 复用 A-1 裁定（禁用 `timeScale`）。
