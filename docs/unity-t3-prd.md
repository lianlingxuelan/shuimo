### 0.1 原始需求复述

T2 已经把「逻辑内核 → 能用键盘玩」这条链路打通：能走、能砍、怪能追、血能掉、种子能复现。但**这套战斗只有一个动作**——按住攻击键，靠冷却自动挥砍，玩家在整场战斗里唯一的决策是「往哪边走」。T3 要做的是**把战斗层做厚**：给玩家多种可选择的行动（技能 / 闪避 / 资源管理），给敌人可被读懂的行为（前摇 / 警戒 / 包围），并引入持续性状态（Debuff）让每一次交手产生「后效」，从而把战斗从「数值对撞」升级为「有选择、有读招、有代价」的攻防循环——**且全程不重写 T2，不动 U1 已验收的平衡口径**。

## 1. 产品目标

**一句话**：T3 要解决的核心体验问题是——**T2 的战斗只有「按住一个键换血」一个动作，玩家没有可做的选择，敌人也没有可被读懂的破绽，战斗因此没有厚度。**

展开为三个正交目标：

**G1 · 战斗表达从「一招」到「一套」。** 玩家手上要有 ≥3 种性质不同的攻击手段（单体快刀 / 群体震开 / 附着 DOT）与 1 种防御手段（闪避无敌帧），并被一个共享资源池（灵力）约束——**任何一次「放大招」都必须以「接下来几秒只能普攻走位」为代价**。判定标准：一场遭遇战中，玩家的按键序列不再是「按住左键 + WASD」，而是能被复盘出「起手 → 铺状态 → 拉开 → 闪避 → 收割」这样的决策链。

**G2 · 敌我之间形成可读的攻防循环。** 敌人的每一次威胁都要有肉眼可辨的前置信号（T2 的 0.35s STRIKE 蓄力窗是起点，T3 要把「警戒 → 包围 → 突击」这条链补完），玩家则要有对应的应对手段（闪避 i-frame / 走位 / 范围技打断站位）。判定标准：一个第一次上手的人，在被突刺打中 3 次之后，能自己总结出「看到怪站定就翻滚」这条规律——**战斗可被学习，而不是只能被承受**。

**G3 · 深化不破内核。** 所有新机制（技能、状态、资源、AI 扩态）的**计算部分**必须以纯逻辑增量落在 `Xianxia.Combat`（`noEngineReferences=true`），确定性可对拍、可 headless 跑；U1 已验收的平衡口径（`PlayerHpMax=260`、`d_eff=4.0`、围攻/单挑 2.5294x、单挑 38.2s / 围攻 15.1s）在「关闭玩家新增主动能力」的基线配置下必须**零回归**。判定标准：T3 合入后，Python 对拍与 NUnit 既有用例**全部原样通过，一条都不改断言**。

> **本阶段不追求**：数值成长（等级/境界/属性点）、装备与词条、技能树与技能升级、掉落与背包、多区域内容量、美术表现。凡与「把当前这一场战斗打得更有厚度」无关的需求，一律后置。

## 4. 需求池

> **优先级定义**：**P0** = 必须有，缺任何一条则「T3 = 战斗深化」不成立；**P1** = 重要，缺失不阻塞验收但战斗厚度打折；**P2** = 可选增强，时间允许再做。
> **验收标准**均要求可在 Unity Editor PlayMode 中当场人工复核，或由 NUnit / Python 对拍自动断言。

### 4.1 P0 · 必须（T3 骨架，9 条）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| **T3-P0-01** | **动作帧机 `ActionState`（纯逻辑）**。为玩家建立统一的动作状态机：`IDLE / ATTACK / CAST / DODGE / HITSTUN`，每个动作由 `startupFrames / activeFrames / recoveryFrames` 三段帧数据描述，附加可选的 `iframes` 与 `cancelWindow`。**这是技能、连招、闪避三者的公共地基**——没有它，三个系统会各写一套计时器，后续必然打架。帧数以 60Hz 逻辑步为基准（对齐 `CombatScheduler.FixedStep=1/60`）。 | ① 同一动作在 30fps / 60fps / 144fps 下经历的**逻辑帧数完全相同**；② 后摇期间再次输入被拒绝，落在 `cancelWindow` 内的输入被接受；③ 动作进行中被破韧硬直可强制中断并回到 `HITSTUN`；④ 纯逻辑层可 headless 单测，无 UnityEngine 引用。 |
| **T3-P0-02** | **技能系统框架（纯逻辑）**。`SkillDef` 静态定义表（id / 形状 shape ∈ {sector, circle} / range / arc / forward / raw / poiseDamage / cooldown / qiCost / frameData / statusEffects[]）+ `SkillRuntime` 运行时（每技能独立 CD 计时、施法前置校验：CD 就绪 && 灵力充足 && 当前动作可被取消）。命中判定为纯几何函数，与 `AttackController` 现有扇形判定同源。 | ① 技能定义全部数据化，不得在代码里硬编码任何数值；② CD 未就绪 / 灵力不足时施法请求被拒绝且不进入前摇（不空放不扣资源）；③ 命中集合与手工计算的几何结果一致（单测覆盖扇形边界 ±45°、圆形边界、贴脸 d≈0 三种退化情形）；④ 一次施法对范围内每个目标各结算一次（AOE 语义，与 T2 一致）。 |
| **T3-P0-03** | **灵力（Qi）资源池（纯逻辑）**。挂在 `Combatant` 上：`Qi / QiMax`，自然回复，脱战加速回复；技能施放前扣除，不足则拒绝。**建议占位值**：`QiMax=100`、战斗中回复 `8/s`、脱战（2s 内未攻击且未受击）回复 `×2`。 | ① 灵力不足时技能不触发且 HUD 给出明确反馈（灵力条闪红）；② 连续施放最贵技能会在 ≤3 次内耗尽灵力（验证资源是真约束而非摆设）；③ 灵力回复与逻辑帧同步，帧率无关；④ **玩家不施放任何技能时，灵力系统对承伤链路零影响**（U1 基线不变）。 |
| **T3-P0-04** | **首发技能 3 个（数值层）**。见 §4.4 技能表。其中 `skill_basic_slash`（普攻）**必须与 T2 完全同口径**：`raw=12` / `CD=0.4s` / 扇形 `r=70` / `90°` / 灵力消耗 0。另两个为群体震开型与 DOT 附着型。 | ① 普攻手感与 T2 完全一致（同样三到四刀清一只幽篁小怪）；② 三个技能在**性质**上可区分：单体快 / 群体带击退 / 单体低伤高状态；③ 每个技能都有独立可辨的占位 VFX 与音效钩子（无音效资源时留空实现）；④ 技能数值全部来自配置，改数不需重新编译内核。 |
| **T3-P0-05** | **主动闪避 Dodge（纯逻辑 + Unity 输入）**。按键触发：朝当前输入方向（无输入则朝面向）位移，位移期间获得无敌帧。**建议占位值**：总时长 `0.24s` / 位移 `130px` / i-frame `0.20s`（起始第 3 帧生效）/ 消耗体力 `25` / CD `0.8s`。实现上**直接置 `WCoreState.Iframe`，不启用 `DodgeEnabled` 随机骰**——两条路径必须物理隔离。 | ① i-frame 期间敌人接触伤害与 BOSS 冲击波均不生效，且 W-CORE 冷却表**不被消耗**（不能出现「翻滚吃掉了下一次真实伤害的冷却」）；② 闪避可从普攻后摇的 `cancelWindow` 中取消出来；③ 体力不足时无法闪避；④ **`DodgeEnabled` 保持默认 false，既有对拍断言一字不改仍然通过**。 |

| **T3-P0-09** | **确定性与平衡回归护栏（工程约束）**。① 所有新增逻辑（技能 CD、灵力回复、状态跳伤、AI 扩态）必须在 `Encounter.StepFixed` 的固定步内推进，**新增阶段插入位置需在文档中显式声明**并随代码评审；② Python 对拍新增技能/状态/闪避用例；③ **U1 平衡基线回归**：在「玩家不施放技能、不闪避、灵力系统空转」的基线配置下，单挑 38.2s / 围攻 15.1s / 倍率 2.5294x 必须复现。 | ① 同种子文本 diff 在 T3 前后对「纯承伤场景」输出**逐字节一致**；② 既有 Python 对拍 64/64 与 NUnit 88 用例**全部原样通过，断言不得修改**；③ 新增用例全 PASS；④ 若任一既有断言需要修改，必须先提变更评审，不得静默改数。 |

| **Q6** | **帧数据单位**：帧（60Hz 整数）vs 秒（float）。PM 建议**用帧**——内核 `FixedStep=1/60` 天然对齐，整数无浮点漂移、对拍更稳，且与 Godot 设计文档同口径便于对照。代价：若将来要支持 120Hz 逻辑帧需全表换算。 | 用帧，并锁定 60Hz 逻辑帧 | 内核数据结构、对拍稳定性 |
| **Q7** | **Debuff 首批范围**：4 种（无行为禁制）vs 直接上 9 种（含冰冻/麻痹等硬控）。PM 建议**先 4 种**——硬控会双向作用（怪被冻 = 玩家少挨打、玩家被冻 = 玩家多挨打），**直接改写 U1 的 TTK 口径**，需要一轮完整的数值回归。先用 4 种把框架跑通，硬控随 P1-04 单独评审。 | 首批 4 种（灼烧/蛊毒/迟滞/破防） | U1 平衡回归工作量 |
| **Q8** | **闪避与对拍基线的隔离**。PM 方案：主动闪避**直接置 `WCoreState.Iframe`**，完全不启用既有的 `DodgeEnabled` 随机闪避骰；对拍基线继续保持 `DodgeEnabled=false`。这样既有 88 条 NUnit 与 64 条 Python 对拍**一条都不用改**。请确认这个隔离策略。 | 采纳隔离策略 | 对拍基线完整性（G3 的核心保障） |
| **Q9** | **U1 平衡窗口是否需要重定义**。U1 的「单挑 38.2s / 围攻 15.1s」衡量的是**玩家被打死的时间**。T3 加入闪避后，熟练玩家的实际生存时长会显著变长（可能翻倍）。请拍板：① 基线回归**仍以「关闭闪避」配置**为准（PM 建议，保护既有断言）；② 是否需要额外定义一个「开启闪避」的新平衡窗口作为 T3 的观测指标（PM 建议：本阶段只记录不设阈值，T4 再定）。 | ①按关闭闪避回归；②只记录不设阈值 | 验收口径、后续数值基线 |
| **Q10** | **敌人是否技能化**（P1-08）。小怪目前只有「接触伤害 + STRIKE 突刺」。给小怪配 1 招带前摇的技能能大幅提升读招博弈，但会引入新的伤害来源，**必须重跑平衡回归**。是否在 T3 内做？ | 列 P1，视 P0 完成情况决定 | 平衡回归、AI 复杂度 |
| **Q11** | **asmdef 方案**：新建 `Xianxia.Unity.T3` vs 复用 `Xianxia.Unity.T2`。PM 建议**复用 T2**——T3 的表现层与 T2 高度耦合（`AttackController` 要降级、`Hud` 要扩展、`CombatBridge` 要改），拆两个 asmdef 会立刻产生「T3 引用 T2、T2 又要回调 T3」的循环引用，收益为零。纯逻辑侧则以**新建子目录**（`Skills/`、`Status/`）保持结构清晰。 | 复用 `Xianxia.Unity.T2` | 工程结构、编译依赖 |
| **Q12** | **锁定索敌是否 T3 必做**（P1-05）。PM 建议：**若 Q3 拍板 BOSS 进 T3 P0，则锁定同步升 P0**（BOSS 战没有锁定会非常难受）；若 BOSS 留 P1，锁定也留 P1。P0 阶段先用「软索敌 ±15° 吸附」（T3-P0-07）以极低成本覆盖 80% 的「砍空」挫败感。 | 与 Q3 联动决策 | 移动/相机耦合度、T3 工作量 |

## 8. 裁定理由速查（为什么这么排优先级）

| 候选能力 | 裁定 | 理由（工作量 / 内核侵入度 / 体验优先级） |
|---|---|---|
| ① 技能系统（多技能 + CD + 资源） | **P0** | 体验优先级最高——**没有它 T3 就不叫战斗深化**。侵入度中（新增为主，`Encounter` 顺序需谨慎）。工作量中。 |
| ③ 闪避 / i-frame | **P0** | 唯一的防御手段，是「读招」闭环的另一半。侵入度**极低**——`WCoreState.Iframe` 已存在，只需一条独立触发路径。性价比最高的一项。 |
| ⑤ Debuff 9 种 | **框架 + 4 种 P0；余 5 种 P1** | 框架必须 P0（技能没有后效就还是 T2）；但硬控类改写 TTK 口径，拆出来单独评审是对 U1 成果的保护。 |
| ② 连招 / Combo | **P1** | 体验价值高，但**依赖 P0-01 帧机先落地**，且要动 T2 已验证的「按住连挥」手感（Q1）。放 P1 是为了让 P0 的地基先稳。 |
| ⑥ 敌人 AI 七态 | **P1**（`ALERT`/`SURROUND` 优先） | 侵入度中且**直接影响交战节奏 → 影响 U1 的 TTK**，必须在 P0 平衡回归通过后再动。`SURROUND` 单项性价比高，可提前做。 |
| ⑦ BOSS 战 | **P1** | 内核已就绪，**边际成本低**；但依赖锁定 + 可读前摇，独立做效果打折。与 Q3/Q12 联动。 |
| ④ 锁定索敌 | **P1**（P0 只做软吸附） | 会改动移动/朝向/相机三者的耦合，工作量中偏大；而 80% 的挫败感用 ±15° 软吸附即可消除。**先摘低垂果实**。 |
| ⑧ 战力评估 | **P2** | 纯函数零侵入，但**玩家侧体验收益接近于零**（在没有装备与等级的 T3，战力是个不会变的常数）。等 T4 养成线一起做才有意义。 |
| 境界压制 / 五行克制 / 斩杀线 | **延后 T4+** | 这三项都是**伤害乘区**，直接改写 U1 已验收的平衡口径，且依赖尚不存在的境界/五行系统。现在做等于在没有地基的地方砌墙。 |
| 装备 / 词条 / 技能树 | **延后 T4+** | 属养成线，没有掉落与等级作为供给端，装备是孤岛（Q5）。 |
| 仇恨表 HateTable | **延后 T4+** | 单人 PVE 下唯一仇恨目标恒为玩家，**当前收益严格为零**。等仙侣/召唤物出现再做。 |
| 完美格挡 / 蓄力重击 / 暴击 | **P2** | 都是手感增强项，锦上添花；在 P0 的三技能 + 闪避尚未验证好玩之前，加这些只会稀释调优注意力。 |
| 伪高度 z 轴 / 击飞 / 弹道 | **延后 T4+** | 需要改渲染层排序与碰撞模型，是架构级改动，与「战斗深化」的核心诉求不在同一层。 |

## 9. 验收总纲（Definition of Done）

T3 视为完成，当且仅当以下全部成立：

1. **P0 九条全部达成**，每条的验收标准均可在 PlayMode 现场复核；
2. **既有测试零修改全通过**：Python 对拍 64/64 + T3 新增用例、Unity NUnit 88 + T3 新增用例，**不得为了让新代码通过而修改任何一条既有断言**；
3. **U1 平衡回归通过**：在「玩家不施放技能 / 不闪避」的基线配置下，单挑 38.2s、围攻 15.1s、倍率 2.5294x 复现；
4. **确定性保持**：同种子文本 diff 在「纯承伤场景」下 T3 前后逐字节一致；技能/状态/灵力纳入导出后，同种子两次运行结果一致；

6. **Q1~Q12 全部有明确拍板结论**，并回写进本文档 v1.1。
