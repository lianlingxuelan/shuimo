# 第一章事件闭环设计：初入幽篁

## 目标

在现有竹海场景中完成一条无需切场景的可玩主线：玩家前进、遇怪、击败敌人、与 NPC 对话、进入商店、完成章节提示。它复用现有移动、战斗、采集、背包和调理系统，不改变战斗内核推进权。

## 美术与交互原则

- NPC 采用水墨人物贴图（前景立绘 + 轻微呼吸/朝向变化），不是 3D 人偶。
- 建筑采用可替换的三层 2D 贴图：主体、屋檐前景、招牌；后续可替换为 Blender 模型而不改事件代码。
- 所有对话、商店、章节弹窗使用统一“宣纸册页”：深墨投影、暖宣纸底、细墨分隔线、印章式按钮。
- 事件区不创建刚体物理链；由剧情导演按玩家与节点的距离检测，避免改变现有 PlayerController。

## 玩家路径与场景节点

第一版在当前竹海主路上布置五类节点，位置以 `WorldBuilder.PlayerSpawn` 为基准计算，避免将世界坐标写死在多个脚本中：

1. **起点**：显示“第一章：初入幽篁”，目标是沿主路前行。
2. **拦路怪节点**：玩家进入前方半径后唤醒唯一剧情怪；它复用敌人现有追击、受击、掉血和死亡表现。
3. **引路 NPC 节点**：仅在剧情怪死亡后显示。靠近时出现交互提示。
4. **竹市小铺节点**：NPC 对话选择“进入小铺”后高亮；靠近建筑仍可再次打开商店。
5. **章节终点**：首次打开商店后显示第一章完成，并指向后续药庐/客栈预留位。

可扩展建筑预留：主路左侧药庐，右侧客栈，远端山门。它们使用同一种 `StoryLocation` 描述，后续只添加数据，不复制触发逻辑。

## 结构

### StoryEventDirector

挂在 `WorldBuilder` 生成的世界根，持有唯一章节状态机：

`Opening -> TravelToRoad -> DefeatRoadEnemy -> MeetGuide -> VisitShop -> Completed`

它只读取玩家位置、敌人存活状态和 UI 回调；不直接写玩家 HP、怪物 HP、移动速度或 `Time.timeScale`。状态推进与位置判断为纯规则类，单元测试不依赖 Unity 场景。

### StoryLocation 与 StoryActorView

`StoryLocation` 是位置和触发半径的数据组件。`StoryActorView` 负责 NPC/建筑的贴图分层、排序与显示/隐藏。它们不决定剧情顺序；导演只切换它们的可见性与高亮。

### DialogueBookHud 与 ShopBookHud

两者共用册页风格和打开/关闭规则：

- NPC 对话：逐句显示，引路人提供“交谈 / 进入小铺 / 离开”。
- 商店：第一版只提供真实材料交易，消耗已有 `PlayerInventory` 的竹材，换取现有系统可识别的嫩笋；交易前后即时刷新行囊。
- 章节：顶部显示当前章节名和一句明确目标，关键状态转换时给一次短提示。

UI 打开时不暂停世界，也不吞掉已有战斗技能栏；`Esc` 优先关闭最顶层册页。

## 失败与边界

- 剧情怪未准备好时，节点保持“前路有异动”且不推进，避免空引用直接跳章。
- 对话或商店关闭不会推进章节；仅成功进入商店才进入 `VisitShop`。
- 材料不足时按钮保留并解释所需竹材，绝不扣成负数。
- 同一事件节点只触发一次；按 R/场景重建时，导演随世界根销毁重建。

## 测试与验收

先为纯 `FirstChapterRules` 编写失败测试，覆盖：

1. 玩家走到路口只会从前进状态进入遇怪状态。
2. 剧情怪死亡前，NPC 不可见且不可交谈。
3. 敌人死亡后，NPC 出现且只能通过商店入口完成章节。
4. 材料不足的交易不改变背包。
5. 同一状态事件重复触发不会重复发章或重复生成 NPC。

Unity 验收时，从 Play Mode 实测完整路径：前进、战斗、NPC、对话、小铺、章节完成；并检查打开册页不会中断攻击、采集或技能栏。

## 非目标

- 不在本章引入完整 3D NPC / 房屋模型、寻路网格、金币经济或多地图加载。
- 不改现有敌人 AI、CombatBridge 内核和玩家移动实现。
- 药庐、客栈、山门仅作为可见预留建筑，本章不实现各自完整玩法。
